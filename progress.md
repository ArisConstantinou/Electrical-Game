## 2026-09-22 · Hammer frame-spike isolation, no accepted runtime shortcut

- `mobile-work-profile.mjs` now records the wall's existing geometry telemetry and waits for startup geometry before resetting peak latency on hammer runs. This separates startup mesh latency from impact-time latency without changing game behavior. At 390×844 DPR3 on the current Windows host, a 15-impact diagnostic measured p95 20.7 ms, `MasonryVolume.impact` worst 13.3 ms, main-thread mesh-job dispatch worst 5.6 ms, and post-startup accepted geometry latency peak 114.2 ms. The metrics overlap inside `game.step`; they must not be added as independent frame costs.
- A one-job-in-flight trial moved less work into a strike but did not show a reliable frame-time win. An idle-callback dispatch moved mesh export off the strike and kept authoritative raycasts immediate, yet comparable output lag rose to 300.7 ms while p95 was 22.2 ms; it was removed. Reusing exposure offsets and caching the XY color variation both preserved exact material/mesh oracle results but did not improve live p95 or mesh-job totals convincingly, so both were removed. `BrickWall.ts` and `MasonryVolume.ts` match their pre-trial Git blobs. Further speed work must reduce the impact algorithm's own cost or move exact extraction off the main thread with authoritative mass/hitboxes and tightly bounded visible update latency, rather than hiding work in a queue.
